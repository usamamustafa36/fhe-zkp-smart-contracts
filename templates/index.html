📝 Step 1: Enter First Number

📖 What is happening?
You are entering the first number that will be processed through our privacy-preserving system. This number will be validated, encrypted, and used in a computation without ever exposing its plaintext value.
🔍 WHAT:

Entering a numeric value that will be encrypted using Fully Homomorphic Encryption (FHE). The system will validate the input using Zero-Knowledge Proofs (ZKP) to ensure it's within acceptable range.

❓ WHY:

Input validation prevents malicious or invalid data from entering the system. ZKP validation ensures the input is legitimate without revealing the actual value to the validator.

⚙️ HOW:

The system checks if your number is between -1,000,000 and 1,000,000. If valid, it generates a cryptographic proof (ZKP) that proves the number is in range without revealing the number itself.

📝 Step 2: Enter Second Number

📖 What is happening?
You are entering the second number that will be added to the first number. Both numbers remain encrypted throughout the computation, ensuring complete privacy.
🔍 WHAT:

Entering a second numeric value that will also be validated with ZKP and encrypted with FHE. This creates two separate encrypted ciphertexts that can be mathematically combined.

❓ WHY:

Having two encrypted inputs allows us to demonstrate homomorphic addition - performing computation on encrypted data without decrypting. This is the core power of FHE.

⚙️ HOW:

Same process as Step 1: ZKP validation ensures the number is valid, then FHE encryption transforms it into a ciphertext that preserves mathematical operations.

3

🧮 Step 3: Homomorphic Addition (FHE Computation)

📖 What is happening?
This is the magic of Fully Homomorphic Encryption! We are adding two encrypted numbers together WITHOUT decrypting them first. The computation happens entirely on ciphertexts.
🔍 WHAT:

Performing addition operation on two encrypted ciphertexts. The FHE scheme (CKKS) allows us to perform arithmetic operations directly on encrypted data, producing an encrypted result.

❓ WHY:

This enables computation on sensitive data without exposing it. The server/blockchain can perform calculations without ever seeing the plaintext values - perfect for privacy-preserving smart contracts.

⚙️ HOW:

The CKKS FHE scheme uses polynomial arithmetic over encrypted data. When we add two encrypted values, the result is also encrypted and can be decrypted to reveal the sum of the original plaintexts.

🔬 Technical Details:

• FHE Scheme: CKKS (Cheon-Kim-Kim-Song) - supports floating-point arithmetic

• Operation: Homomorphic addition of two ciphertexts

• Result: Encrypted sum (ciphertext) that can be decrypted to get the actual sum

• Security: Original values remain completely hidden during computation

4

🔓 Step 4: Decrypt the Result

📖 What is happening?
We are now decrypting the encrypted sum to reveal the final result. This demonstrates that the FHE computation was performed correctly - the decrypted result matches the expected sum of the two original numbers.
🔍 WHAT:

Decrypting the encrypted result using the FHE decryption key. This reveals the plaintext sum that was computed entirely on encrypted data.

❓ WHY:

Decryption verifies the correctness of the homomorphic computation. We can confirm that the encrypted addition produced the correct result without exposing the inputs during computation.

⚙️ HOW:

The FHE decryption algorithm uses the secret key to transform the encrypted result back into plaintext. The decrypted value should match the sum of the two original numbers.

🔬 Technical Details:

• Decryption Key: Secret key held by the data owner (not exposed to blockchain)

• Verification: Compare decrypted result with expected sum (Number 1 + Number 2)

• Accuracy: FHE introduces small approximation errors; we verify correctness within tolerance

5

⛓️ Step 5: Submit to Blockchain

📖 What is happening?
We are recording the entire computation on the blockchain, including ZKP proofs, encrypted inputs, and results. This creates an immutable, transparent audit trail while maintaining privacy (only encrypted data is stored).
🔍 WHAT:

Submitting a blockchain transaction containing: ZKP proofs (validates inputs), encrypted inputs, encrypted result, and metadata. This creates a permanent, verifiable record.

❓ WHY:

Blockchain provides transparency and auditability. Anyone can verify that a computation occurred and that inputs were validated, without seeing the actual sensitive data (it's encrypted).

⚙️ HOW:

The transaction is signed and broadcast to the blockchain network. It gets included in a block, creating an immutable record. The transaction hash serves as proof of the computation.

🔬 Technical Details:

• Transaction Contents: ZKP proofs, encrypted inputs, encrypted result, operation type, timestamp

• Privacy: Only encrypted data is stored on-chain; plaintext values never appear

• Verifiability: Transaction hash and block number provide proof of computation

• Network: Local (simulated) or Sepolia (public, verifiable on Etherscan)
